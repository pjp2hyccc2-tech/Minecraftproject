# FROSTBOUND: THE LAST HEARTH

Minecraft 1.20.1 / Forge 47.4 向けの都市運営サバイバルMOD。凍りついた世界で、人類最後の都市を熱源炉ひとつで100日間存続させます。

バージョン 0.7.0-build7（BUILD 0〜7）

## 動作環境

- Minecraft Java Edition 1.20.1
- Forge 47.x（47.4.0 以上を推奨）
- Java 17
- 必須の前提MODなし（シミュレーション本体は jar に同梱）

## 導入

1. Forge 1.20.1（47.4.0 以上）をインストールする。
2. `frostbound-0.7.0-build7.jar` を `.minecraft/mods/` に入れる。
3. 起動するとタイトル画面に「FROSTBOUND：新しい都市を築く」ボタンが出る。

## 遊び方

1. タイトルの「新しい都市を築く」で、難易度・1日の長さ（10/20/30/60分）・都市名・ガイドの有無を決める。
   「ワールド新規作成」でワールドタイプに FROSTBOUND を選んでもよい（その場合は入った後に建設画面が開く）。
2. 凍土ディメンションの広場に立つ。中央に熱源炉、周りに避難小屋2棟・倉庫・採炭場、市民30人。
3. **M キー**で管理モード。上空カメラで都市を見下ろし、10個のタブで運営する。
   - WASD/矢印：移動　Q/E：回転　ホイール：ズーム　右ドラッグ：視点　中ドラッグ：平行移動
   - H：熱マップ　Space：一時停止　1/2/3：速度　R：建物の向き　右クリック：配置取消
4. 建設タブで建物を選び、地面をクリックして配置。緑なら建設可、赤なら理由が表示される。
   作業員が足場を組み、ブロックで実際に建物が建っていく。
5. 熱源炉の出力（L0〜4、研究でL4）・過負荷運転・石炭の確保・住居・食料・医療・法律・研究・遠征をやりくりし、
   寒波と100日目前後の大寒波を越える。
6. 100日目を越えると結末（5種類）。生き残った場合は「都市を存続させる」でエンドレスへ。

建物の操作盤（オレンジのパネル）や熱源炉の制御核を右クリックすると、その建物の画面が開きます。

### 主なルール

| 項目 | 内容 |
| --- | --- |
| 時間 | 1日 = 1200ステップ（既定20分）。一時停止・1x/2x/3x。オフライン中は進まない。サーバーに誰もいない間も止まる |
| 熱 | 供給率 f = min(1, 出力/需要)。距離減衰 η（半径の6割まで1、半径で0.5）。室温 = 外気 + 断熱 + f·η·上昇幅（30ステップ遅れ） |
| 資源 | 石炭・木材・鉄・食料・医薬品・熱核。負にならない。倉庫で上限が増える |
| 市民 | 一人ずつ健康・満腹・体温・疲労・希望・不満・病気を持つ。近くの市民だけNPCとして表示（LOD） |
| 待機中の市民 | 勤務時間中に雪の下の廃材を拾う（木材0.25・石炭0.1/人・時）。資源が尽きて建設不能になることはない |
| 建設 | 作業員が足りなければ、重要度の低い職場から一時的に人を借りる（医療施設からは借りない） |
| 専門職 | 医師・技師・技術員・探索員は、自分の職種の施設に空きがあればそちらへ優先して戻る |
| 法律 | 10種。1日1つまで。希望・不満と生産・医療・労働時間などに効く |
| 研究 | 8分野25項目。研究所に技師を配置して進める |
| 難易度 | 易しい／普通／過酷：気温補正、初期資源、石炭消費、病気と寒さの危険度、寒波の回数 |

## コマンド（OP権限）

`/frostbound status | found [難易度] [分] | advance <時間> | speed <1-3> | pause | resume | daylength <分> |
weather <天候> | give <資源> <量> | event <id> | tp`

## 設定（`config/frostbound-common.toml`）

管理画面中の自動一時停止（既定オフ）、イベントの自動表示、新規都市の1日の長さ、専用サーバーの難易度、
NPCの表示数と半径、日次バックアップの保持数。

## 保存

都市の状態はワールドの `data/frostbound_city.dat` に保存されます。

- 一時ファイルに書いてから置き換え、直前の版を `.bak` に残す（書き込み中に落ちても壊れない）。
- 1日ごとに `frostbound_city.day-NNNN.bak` を作り、設定した数だけ残す。
- 読めないファイルは `.corrupt-*` に退避し、最新の読めるバックアップから自動で復元する。
- スキーマの移行処理あり。新しい版のMODで保存したデータは読み取り専用として開き、上書きしない。

## 構成

| パス | 内容 |
| --- | --- |
| `core/` | シミュレーション本体（純Java、Minecraft非依存、JUnit 19件） |
| `src/main/java/com/frostbound/server` | 都市サービス（時間・天候・同期・保存・保護）、建物の生成、市民NPCのLOD |
| `src/main/java/com/frostbound/world` | 凍土ディメンション（固定地形のチャンク生成、バイオーム） |
| `src/main/java/com/frostbound/client` | HUD、管理モード（カメラ・10タブ・熱マップ・配置）、各画面、霧・雪・環境音 |
| `src/main/java/com/frostbound/selftest` | 専用サーバーでの2段階セルフテスト |
| `src/main/resources` | ディメンション/バイオーム/ワールドプリセット、テクスチャ・音・日英の言語ファイル |
| `tools/` | テクスチャ・音の生成スクリプト、言語ファイルの生成、バランス検証用の自動プレイヤー |
| `.github/workflows/frostbound.yml` | ビルド → サーバーセルフテスト → クライアント自動スクリーンショット |

## ビルドとテスト

`frostbound` ブランチへの push ごとに GitHub Actions が次を実行し、結果（jar・ログ・テスト結果・スクリーンショット）を
`frostbound-ci` ブランチに出力します。

1. `./gradlew build`（コンパイル、core の単体テスト、API互換チェック）
2. 専用サーバーのセルフテスト：新規ワールドで都市建設・建物ブロック・配置規則・建設・熱・法律・研究・3日間の進行・保存を確認し、
   再起動後に保存内容が完全一致すること・建物・バックアップ・継続動作を確認
3. Xvfb 上でクライアントを起動し、建設画面・HUD・管理モード全タブ・熱マップ・配置・建物画面・イベント・吹雪・夜を撮影

手元では JDK 17 で `./gradlew build`。jar は `build/libs/` にできます。

バランス確認：`tools/balance/Bot.java`（各難易度を自動プレイヤーで100日回す）。

## 既知の制限

- 地形は全ワールド共通の固定マップ（都市の中心は常に原点）。
- 遠征はUI上の地点リストで管理し、ワールド上の別地点へ実際に移動はしない。
- プレイヤー自身は寒さでダメージを受けない（凍えるのは市民）。
- バランス値の外部JSON上書きは未対応（値はコード内）。
