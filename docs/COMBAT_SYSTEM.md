# 戦闘システム設計（Phase 2）

> 状態: **Phase 2 で実装中**。各項目の検証状況は TEST_PLAN.md の Phase 2 章を参照。
> ここに「Phase 3 以降」と書かれたものは**まだ存在しません**。

## 1. 目標

- Minecraft標準のクリック戦闘から、コンボ・強攻撃（溜め／派生）・回避・ガード・パリィ・武器スキルのあるアクション戦闘へ。
- **操作レスポンス最優先**（入力→モーション開始はクライアントで即時）と、**判定・ダメージ・クールダウン・スタミナのサーバー検証**を両立する。
- ステータス（STR/VIT/AGI/LUK）を戦闘に反映する（D-011 の Phase 2 分）。INT（魔法）と DEX（遠距離・命中）は杖・弓とともに Phase 3。

## 2. 操作（初期設定。オプション → 操作設定 → ETERNAL REALM で変更可能）

| 入力 | 動作 | 備考 |
|---|---|---|
| 左クリック | 通常攻撃（武器ごとに2〜4段コンボ） | 押し続けても連打にはならない（1クリック=1入力）。先行入力1回分を受け付ける |
| R 押し続け → 離す | 強攻撃（溜め）。溜め時間で威力上昇、最大で自動発動 | 通常攻撃コンボ中に入力すると**派生強攻撃**（威力ボーナス） |
| 右クリック 押し続け | ガード（前方の攻撃を軽減、スタミナ消費） | **押した直後の短い時間に受けるとパリィ**（無効化＋相手をひるませる＋反撃ボーナス）。連打では受付が開かない（前回から0.8秒以上） |
| しゃがみ＋右クリック | オフハンドのアイテムを使う（食べ物・盾・松明など） | 武器を持っている間、通常の右クリックはガード専用 |
| 左Alt | 回避（移動入力の方向へステップ、入力なしなら後方）。短い無敵時間 | 騎乗中・エリトラ滑空中は不可 |
| Z | 武器スキル（武器ごとに1つ、クールダウンあり） | 狙うスキルは**長押しでロックオン**（下記） |
| V / G / B / N / J | 職業スキル（スキル枠 1・2・3・5・6） | 枠に入れるスキルはスキル画面で選ぶ（modules/skills.md）。狙うスキルは長押しでロックオン |
| H | 必殺技（スキル枠 4） | 同上 |

**スキルのロックオン（D-LOCKON、2026-11-11）**: 当てにくいスキルのために、**狙うスキル**（飛び道具・斬撃や突き・前方の円・
狙った場所や前方に置く範囲・前への突進や跳躍）はキーを**押し続けると狙い**、**離すと撃つ**。押してから0.2秒（4tick）
たつと、照準に一番近い敵（スキルの届く距離＝6〜32ブロック、視線が通る、照準から40°以内。照準からの角度＋距離×0.5 が
いちばん小さい敵。今の敵より6以上よい敵が出たときだけ乗り換える）の**縁が白く光る**（バニラの発光の輪郭をクライアントだけで点ける）。
離すとプレイヤーがその敵を向き、スキル要求に敵のIDを付けて送る。サーバーは敵を検証し、スキルの開始と各命中の直前に
プレイヤーをその敵へ向け（近接の形・突進の向き）、飛び道具は真ん中の1発が敵へ曲がり（追尾）、上から降る弾は敵の上から落ち、
狙った場所に置く範囲は届くなら敵の足元に置く。**短く押す（0.2秒未満）と従来どおり即座に撃つ**。**範囲攻撃**（自分の周りの円だけ・
回復・強化）は押した瞬間に撃つ（変更なし）。クールダウン中のスキルは押した瞬間に理由を表示。分類は `job.SkillAiming`
（職業スキル 140 が狙うスキル、80 が範囲・回復・強化）。

ETERNAL REALM の武器を持っている間は、バニラの左クリック攻撃・ブロック破壊は行われません（武器は採掘道具ではない）。
他のアイテムを使用中（盾を構える・食べる・弓を引く等）は攻撃・回避・スキルはできません（D-036）。
バニラの剣や素手などは従来どおりバニラの戦闘です（D-028）。
**職業で使える武器が決まっています**。使えない武器では通常攻撃・溜め・ガード・スキルをサーバーが拒否し（結果 `REJECTED_JOB_WEAPON`）、クライアントも同じ判定で使える武器を案内します。回避だけは常に可能です。

## 3. 権威モデル

```
クライアント: 入力 → ローカルの同じ状態マシンで予測（モーション・効果音・スタミナ表示）→ 意図だけを送信（行動ID・連番・回避方向）
サーバー:     ServerPacketGuard（送信者・レート・ログイン状態）→ 状態マシンで受理/先行入力/拒否を判定
              → サーバーtickで命中判定（サーバー上の位置と向き）→ ダメージ計算・適用 → 結果を返送
クライアント: 連番つきの確認（受理/拒否、スタミナ、クールダウン）で予測を補正。拒否されたら予測した行動を取り消す
```

- C→S は意図のみ。**ダメージ・命中・対象・座標・クールダウンは送らない**（送っても使わない）。
- 命中判定はヒットフレームのtickに、その時点のサーバー上の攻撃者の位置・向きと対象の当たり判定で行う（溜め中・振りかぶり中に向きを変えれば狙いも変わる）。
- 先行入力: 行動中に届いた入力は1つだけ保持し、キャンセル可能点で実行する。ネットワークの揺らぎで入力が少し早く届いても、正規のコンボが失われない。
- 拒否（行動中で先行入力枠が埋まっている、スタミナ不足、クールダウン中など）は**違反ではない**（遅延で普通に起こる）。違反として数えるのは
  「存在しない行動ID」「範囲外の回避方向」など正規クライアントが絶対に送らない値だけ。
- ETERNAL REALM の武器を持った状態のバニラ攻撃（`Player#attack`）はサーバー側でも無効化する（`Item#onLeftClickEntity`）。
  改造クライアントが通常の攻撃パケットを送っても、武器の性能でダメージを与えることはできない。

## 4. 行動の状態マシン（`combat.Combatant`、サーバーとクライアントで同じコード）

| 状態 | 説明 |
|---|---|
| 待機 | どの行動も開始できる |
| 行動中（通常攻撃・強攻撃・スキル・回避） | ヒットフレームを順に発生。**キャンセル可能点**以降は次の行動を即開始できる |
| 溜め中 | 強攻撃の溜め。離すと発動（最小溜め前に離した場合は最小溜めで発動）。最大溜めで自動発動 |
| ひるみ | ガードブレイク時など。すべての行動を拒否 |
| ガード | 右クリック使用中（バニラの「アイテム使用」状態と同期）。攻撃・スキル・溜めは不可、回避は可。**開始はサーバーだけが判断**し、クライアントは同期された状態に追従する（D-035） |

規則:
- 行動中の入力 → キャンセル可能点前なら先行入力（1つ）、後なら即開始。先行入力は「その時点で直接受け付けられる」ようになった瞬間に開始する
  （回避・スキルは最後のヒットの直後、それ以外はキャンセル可能点）。
- クライアントは要求を送る直前の状態を保存し、サーバーが最新の要求を拒否したらその状態に戻す（予測の取り消し）。
- 回避・スキル・ガードは、すべてのヒットフレームが終わった「硬直」部分をキャンセルして出せる（振りかぶり中は不可＝コミットメント）。
- 回避は溜めをキャンセルできる。
- 武器を持ち替えると、進行中の行動・溜め・先行入力は取り消される（残りのヒットは発生しない）。
- 通常攻撃以外（強攻撃・スキル・回避）を出すとコンボ段数は最初に戻る。最終段の後も最初に戻る。
- AGI による攻撃速度は通常攻撃と強攻撃の時間（振りかぶり・硬直・キャンセル点）に掛かる。スキルと回避は固定。

## 6. 命中判定（`combat.HitGeometry`）

- 原点 = 攻撃者の目の位置、向き = サーバー上の yaw/pitch。
- **扇形**: 水平距離（対象の当たり判定の最近点まで）≤ 半径、かつ対象中心への水平角が半角＋対象の幅分以内。
  高さは目の位置から上1.0・下2.2（足元の低い敵に当たる）＋見上げ／見下ろしで半径×sin(pitch) 分を延長。
- **直線**: 視線方向（pitch込み）の線分から対象の当たり判定までの距離 ≤ 幅。
- **円**: 攻撃者を中心とした水平距離 ≤ 半径（スキル）。
- 対象: 生存している `LivingEntity`。除外 = 攻撃者自身・観戦者・防具立て・自分のペット・同じチームの味方・騎乗関係・
  ほかのプレイヤー（闘技場の試合の相手だけは対象になる＝`PvpRules`。闘技場はまだ無いので現状は常に除外）。
- **味方をすり抜ける**（2026-11-11、レイドで密集しても味方に当たらないように）: プレイヤーは対象外なので、近接・スキル・範囲・
  爆発は味方を素通りして後ろの敵に当たる（最大対象数も味方で消費しない）。MODの矢・魔法弾はサーバーでもクライアントでも
  プレイヤーに衝突しない。バニラの飛び道具（矢・雪玉・釣り針など）はプレイヤーが撃ったものなら他のプレイヤーへの着弾を
  取り消して飛び続ける（`CombatEvents.onProjectileImpact`）。武器を持たない左クリックが他のプレイヤーを指していたら、
  その奥の生き物に当たる（`ClientForgeEvents.attackThroughPlayer`）。バニラの攻撃・効果によるプレイヤー間のダメージも
  `LivingAttackEvent` で取り消す。
- 視線: 攻撃者の目から対象（最近点・中心）へのブロック衝突判定。壁越しには当たらない。
- 1フレームの最大対象数: 扇形8・直線6・円12（近い順）。同じフレームで同じ対象には1回だけ。

## 7. ダメージ・ステータス（`combat.CombatStats`、係数はサーバー設定 `combat` で変更可・再読込可）

```
攻撃倍率   = 1 + STR × 0.02
ダメージ   = 武器基礎攻撃力 × 攻撃倍率 × 行動倍率 × (溜め・派生・反撃の倍率)
クリティカル: 確率 = 5% + LUK × 0.2%（上限75%）+ 武器補正、倍率 ×1.5
最大HP     = 20 + VIT × 0.4 + (レベル−1) × 0.5    … バニラの MAX_HEALTH に属性修飾子として反映
被ダメージ軽減（攻撃者のいるダメージのみ）= 防御 / (防御 + 100)、防御 = VIT × 0.5（上限75%）
攻撃速度   = 行動時間 × 1 / (1 + AGI × 0.003)（最短 ×0.6）
スタミナ   = 最大 100 + AGI × 0.4、回復 1.0 + AGI × 0.005 /tick（消費後15tickは回復しない、ガード中は半分）
回復薬     = (最大HP × 割合 + 固定値) × (1 + min(50%, VIT × 0.4%))
```

- **HPの自然回復はない**（空腹もない）。HPが戻るのは回復薬・回復スキル・復活・リスポーンだけ（`player.forge.Vitals`、D-VITALS）。
  回復薬3種は共通のクールダウン: 戦闘中15秒、戦闘外（5秒間ダメージを与えも受けもしていない）2秒。

- 例: Lv1（全ステータス5）の片手剣1段目 = 6 × 1.10 = 6.6（ゾンビ20HPを3段コンボで倒せる、バニラの鉄の剣と同程度）。
- 落下・炎・溶岩・窒息など攻撃者のいないダメージには VIT の軽減を掛けない（環境の危険を無効化しないため）。
- コンボ中の敵の無敵時間（バニラの10tick）は ETERNAL REALM の攻撃では無視する（連撃が成立するため）。
- ノックバックは行動ごとの値に置き換える（連撃で敵が射程外へ飛ばないように、通常攻撃は弱く、最終段・強攻撃は強く）。
- INT・DEX の戦闘効果は Phase 3（杖・弓）。キャラクター画面にその旨を表示する。

## 8. 防御（プレイヤーが攻撃を受けたとき）

| 順 | 判定 | 結果 |
|---|---|---|
| 1 | 回避の無敵時間中で、攻撃者・投射物・爆発によるダメージ | 無効（「回避」表示） |
| 2 | ガード中・パリィ受付時間内・正面（ガード角度内）・ガード可能なダメージ | 無効＋攻撃者をノックバック・鈍足、スタミナ回復、反撃ボーナス（「パリィ」表示） |
| 3 | ガード中・正面・ガード可能 | 武器の軽減率で軽減しスタミナ消費。不足ならガードブレイク（ひるみ） |
| 4 | 攻撃者のいるダメージ | VIT の被ダメージ軽減 |

ガード可能 = 直接の攻撃元（近接の攻撃者・投射物）があり、`bypasses_shield` でも爆発でもないダメージ。
`/kill` など無敵を貫通するダメージには一切介入しない。

## 9. ネットワーク（プロトコル 2、詳細は NETWORK_PROTOCOL.md）

| ID | 方向 | パケット | 内容 |

| 3 | S→C | `CombatStatusPacket` | 処理済み連番と結果、スタミナ、スキルCT、防御イベント（回避/パリィ/ガード/ガードブレイク） |
| 4 | S→C | `CombatStatsPacket` | 派生値（攻撃倍率・最大HP補正・軽減率・攻撃速度・クリティカル・スタミナ）… 予測と表示用 |
| 5 | S→C | `DamageNumberPacket` | 自分が与えたダメージの表示（対象位置・数値・クリティカル等） |

- 行動パケットは専用のレート制限（既定 バースト20・毎秒20）。超過分は破棄しフラッドとして数える（違反ではない）。
- 他のプレイヤーへの同期: 腕振り（バニラの振りアニメーション同期）、行動開始・命中の効果音とパーティクル（サーバーから周囲へ配信）、
  ガード姿勢（バニラのアイテム使用状態）、被弾・ノックバック（バニラ）。ダメージ数値は攻撃した本人にだけ表示。
