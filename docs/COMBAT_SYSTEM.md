# 戦闘システム設計（Phase 2・未実装）

> 状態: 設計案。実装は Phase 2。ここに書かれた機能は**まだ存在しません**。

## 1. 目標

- Minecraft標準のクリック戦闘から、回避・コンボ・パリィのあるアクション戦闘へ。
- **操作レスポンス最優先**（入力→モーション開始は即時）と、**判定・ダメージ・クールダウンのサーバー検証**を両立する。

## 2. 権威モデル

```
クライアント: 入力 → ローカルでモーション再生（予測）→ ActionIntent を送信
サーバー:     ActionIntent 検証（状態・クールダウン・武器・スタミナ）→ サーバーtickで判定 → 結果を確定
              → 本人へ ActionResult（承認/却下・確定クールダウン）、周囲へ演出イベント
クライアント: 却下されたらモーションを取り消し、確定値で表示を補正
```

- C→S は意図のみ（アクションID、入力時のクライアントtick、向き）。ダメージ・命中・座標は送らない。
- 命中判定はサーバー側でヒットボックス（武器ごとの形状×モーション時間）を評価。距離・角度・視線を検証。
- クールダウン・コンボ受付時間・回避無敵・パリィ受付はすべてサーバーtick基準。
- ラグ補償は小さい窓（例: 最大150ms相当）に限定し、超過分は不利側に倒す。

## 3. アクション

| アクション | 概要 | 主なサーバー検証 |
|---|---|---|
| 通常攻撃 | 武器ごとの1〜4段コンボ | 攻撃速度（AGI）、コンボ受付時間 |
| 強攻撃 | 溜め／派生 | 溜め時間 |
| 回避 | 短距離移動＋短い無敵 | スタミナ、クールダウン、移動距離 |
| ガード | 被ダメージ軽減（盾・武器） | 向き（正面判定） |
| パリィ | 攻撃直前の受付窓で成功→カウンター | 受付窓（サーバーtick） |
| スキル／必殺技 | 武器固有ソードスキル（企画書の例） | 習得状況、クールダウン、リソース |
| 空中攻撃 | 空中で派生 | 接地状態 |
| 連携攻撃 | パーティーメンバーの行動に派生 | 近接・タイミング |

## 4. ダメージ式（初期案・要調整）

```
物理 = (武器攻撃力 + STR×2) × スキル倍率 × (1 + 熟練度補正)
魔法 = (杖魔力 + INT×2) × スキル倍率
命中/クリティカル: DEX・LUK で補正、クリティカル倍率 1.5
被ダメージ = max(1, ダメージ × 100 / (100 + 防御))、防御 = 防具 + VIT×1.5
最大HP = 基本HP + VIT×10（バニラの属性 MAX_HEALTH に修飾子として反映）
```
Phase 1 のステータス値（`CharacterSnapshot.totalStats`）をそのまま入力として使う。

## 5. 実装単位（Phase 2 の分割案）

1. 戦闘状態マシン（待機・攻撃中・硬直・回避・ガード）とアクション定義（データ駆動）
2. ActionIntent / ActionResult パケットと `ServerPacketGuard` 経由の検証
3. サーバー側ヒット判定とダメージ計算（純粋モジュールでユニットテスト）
4. クールダウン・スタミナ
5. 片手剣の通常攻撃・強攻撃・回避・ガード・パリィを先に完成 → 他武器へ展開
6. ステータス反映（最大HPなど）
7. マルチプレイ同期（周囲への演出配信）

## 6. 完了条件（企画書）

実際に操作して戦える／スキルが正常に発動する／マルチプレイで同期する／不正な攻撃をサーバーが拒否する。
