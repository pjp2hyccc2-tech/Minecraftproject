# ワールド生成（`world.gen` / `world.forge` パッケージ）

異世界アストリアのディメンション `eternalrealm:astoria`。地形はフィールドマップ専用の生成器 `eternalrealm:fields`（海面 y=63、高さ -64〜319）で、
**地形・バイオームの配置・地表・装飾・建造物**をすべてこのモジュールが決める。

| パッケージ | 種別 | 内容 |
|---|---|---|
| `world.gen` | 純粋（Minecraft非依存） | エリアの輪（`AstoriaAreas`）、バイオーム配置（`AstoriaLayout`, `AstoriaBiome`）、ノイズ（`GenNoise`）、ダンジョン入口の座標（`LandmarkSites`）、王都のNPC位置（`HubSpot`）、登録名（`WorldgenIds`） |
| `world.forge` | Forge | バイオームソース、Feature 群（`world.forge.feature`）、王都・入口の建築、移動API、セーブデータ |
| `data/eternalrealm/` | データパック | `dimension/astoria.json`, `dimension_type/astoria.json`, `worldgen/biome`（24）, `worldgen/configured_feature`（49）, `worldgen/placed_feature`（74） |

データパックのJSONは `python3 tools/gen-worldgen-data.py` で生成する（手で編集しない）。生成器は全バイオームの Feature を
**生成ステップごとに1つの共通順序**で並べる（順序が食い違うと「Feature order cycle」でサーバーが起動しない）。
`WorldgenDataTest` が書き出し結果を検査する（順序の循環、参照切れ、バニラ敵対Mobの湧き、未登録の Feature 型・バリアント、翻訳キー）。

## 1. フィールドマップ（`world.field`）

アストリアは「アルセリア王国 周辺フィールドマップ」の通り、北中央の王都を囲む **10のフィールド** でできている（2.1で同心円の7地域から変更。
`FieldLayout.VERSION` = 2）。地形は `FieldChunkGenerator`（`eternalrealm:fields`）が純粋モジュール `FieldTerrain` の高さで列ごとに埋める
（ノイズルーターも洞窟もなし。どのサーバーでも同じ地図）。範囲は x −1700〜1700、z −1500〜1300（約3.4×2.8km）。北と西は越えられない山脈、
南と東は外海。範囲外へ出ると霧に押し戻される（`WorldService`）。古い版のワールドは起動時にアストリアのフォルダだけ作り直す
（`FieldMapMigration`。キャラクターや進行は保持、旧地形にいたプレイヤーは王都へ）。

- 領域は重み付きボロノイ（フィールドごとに複数の種点）をノイズで歪めた座標で求めるので境界は自然に曲がる。地形は隣のフィールドと約100ブロックかけて混ざる。

- 道: 王都の南門・西門・東門から各フィールドへ（`FieldLayout.roads()`、土の道）。転移碑の位置 `FieldLayout.waystones()`（各フィールドと王都の南門前）。

### 1.1 転移碑（`world.field.Waystones` / `world.forge.WaystoneService` / `block.forge.WaystoneBlock`）

各フィールドと王都の南門前、計11基（`FieldLayout.waystones()`）。2ブロックの石碑（`eternalrealm:waystone[half,facing]`、破壊不可、
光源）で、石そのものはブロックモデル、刻まれたルーンの光・足元で回る魔法陣・浮かんで回る水晶と3つの欠片はクライアント（`WaystoneRenderer`）が描く。
どの転移碑かは置かれた位置で決まる（12ブロック以内で最寄りの点）ので、ブロックはデータを持たない。石碑と周りの祭壇はフィールドの
配置物（下記の set pieces）が置く。

- **記録**: 12ブロック以内に近づくと記録（キャラクターの拡張データ `waystones`、シーズンデータと一緒に保存）。メッセージ・音・光。
- **転移**: 転移碑に触れる（右クリック）と転移メニュー（地図＋行き先一覧）。サーバーが `Waystones.check` で検査:
  転移碑のそば（水平7ブロック・上下12ブロック）・行き先を記録済み・行き先のフィールドが解放済み・戦闘中でない（5秒）・前回から8秒。
  到着は行き先の石碑の正面（向いている側）2〜5ブロックの安全な足場、石碑の方を向いて。出発と到着に光と音、画面が白く光る。
- UI: 地図の転移碑マーカー（記録済みは青く光る）、ミニマップにも表示。

### 1.2 フィールドの魔物（`monster.forge.MonsterSpawner` / `monster.MonsterMenace` / `client.monster`）

- 湧き（アストリア）: 生息地（`world.field.Habitats`、157か所、D-HABITATS）ごと。プレイヤーが生息地の中心から 72＋湧く範囲
  （ふだん60）ブロック以内に来ると動き出し、足りない分が生息地の中の空いた場所（プレイヤーから80ブロック以内・9ブロック以上離れ、
  ほかの魔物から5ブロック以上）に現れる。半分に満たない間は0.5秒に7体、それ以降は1.5〜2秒に1体。普段はおとなしく、近づく
  （既定5ブロック、見えていれば）か攻撃すると襲ってくる（`MonsterTempers`）。サーバー全体で 252＋95×人数 体まで、どのプレイヤーからも
  96ブロック以上離れた魔物は5秒ごとの数え直しで消える。アストリアの外ではプレイヤーの周り14〜56ブロックに湧く（近くに74体まで）。
- **徘徊する魔物**（2026-11-14、オーナー「たまに敵がわかない…常に湧くようにして」）: 調べると、フィールドのおよそ半分（フィールド6は
  73%、7と10は約6割）がどの生息地の湧く範囲からも48ブロック以上離れていて、そこでは魔物が一度も現れなかった。いまは生息地の湧く
  範囲から36ブロック以上離れたプレイヤーの周りに、そのフィールドの魔物（その地域の表から、地域の Lv で）が最大16体（生息地の縁の
  近くでは少なめ）、2秒ほどごとに数体ずつ、18〜52ブロック先に現れる。生息地の中・王都・ウェイストーン・ヌシの縄張り・災厄の巣・
  ダンジョンの入口には現れない。おとなしさは生息地の魔物と同じ。プレイヤーが離れれば数え直しで消える（`Habitats.roamersWanted`・
  `roamable`、テスト `RoamingTest`: フィールドのどの開けた場所にも魔物が近くにいる）。
- **湧く場所の判定の修正**（同日）: 雪の層・カーペットの上や道・耕地は「立てない場所」と見なされて湧かなかった（いまは床が半ブロック〜
  1ブロックの高さなら立てる、柵の上は不可）。読み込まれたばかりのチャンクに、そこに保存されている魔物が戻る前に湧かせていた
  （いまはそのチャンクが動き出してから）。バニラの体の魔物（スライム・クモ・クリーパーなど）は32ブロック離れると勝手に消えていた
  （いまは生息地と数え直しが決める）。
- **離れた所の休み**（2026-11-13、D-LIGHTWEIGHT、`monster.MonsterThrottle`、`MonsterEvents.onLivingTick`）: 何もしていない
  （狙いなし・傷なし・地上で止まっている・行き先なし・効果なし・燃えていない・攻撃中でない）フィールドの魔物は、32ブロック以内に
  プレイヤーがいなければ4tickに1回だけ動く（魔物ごとにずらす）。近づく・攻撃される・押される・自分で歩き出すと次のtickから毎tick。
  現れて2秒はいつも毎tick。ダンジョンの波・ボス・プレイヤーのいないレベルは対象外。サーバー設定 `performance.monsterAiThrottle`
  ／`monsterAiThrottleRange`。数（3.5倍）も近くの戦いも変わらない。
- 見た目の格（`MonsterMenace`、レベルは名札から読む）: Lv15〜 そのフィールドの属性の粒子がときどき、Lv25〜 属性色のオーラ、
  Lv35〜 全身に属性色のエネルギーの渦（`MenaceSwirlLayer`、帯電クリーパーの渦テクスチャを色付けして体をなぞる）、Lv45〜 渦が明るく速くなり
  足元から波紋。属性: 草原・農場=光、月影の森=胞子、鉱山=火の粉と煙、滝=霜、遺跡=炎、峰=雷、終焉の森=虚無、湖畔=水、港=風。
- 境目: フィールドの境界に近づくと（12ブロック以内）、境界線に沿って向こう側のフィールドの色の粒が立ちのぼる（クライアントのみ）。

### 1.3 先読み生成（`world.field.ChunkPregenPlan` / `world.forge.ChunkPregen`）

2026-11-13 のオーナーの依頼「12チャンクごとくらいに自動読み込み(通知無し)で入れて動作を軽くする」（D-LIGHTWEIGHT）。地図は
`FieldLayout` で決まっているので、チャンクを先に作っておける。先に作ったチャンクは、プレイヤーが着いたときディスクから読むだけになる
（その場で地形・装飾・建造物を作るよりずっと軽い）。

- 範囲: 地図（x −1700〜1700、z −1500〜1300）と外側8チャンク、約44,000チャンク。
- 順番: まず各プレイヤーに見えている範囲（描画距離）のすぐ外から12チャンク先までの帯を、進んでいる方向の帯の真ん中に近い順
  （止まっていれば近い順）。それが済んだら地図全体を王都から輪のように外へ（`performance.pregenWholeMap`）。
- やり方: チャンクごとにチケットを付けてゲームに作らせ（サーバーを待たせない）、できたら外して保存・解放させる。50秒でできなければ
  いったん外して後でやり直す。平均tickが `pregenMaxTickMillis`（既定35ms）未満のときだけ新しく始め、同時に作る数は2から始めて
  サーバーに余裕があれば `pregenMaxChunksInFlight`（既定6）まで増やし、忙しければ半分に。1tickに始めるのはプレイヤーの先で2つ、
  全体の分は1つ。サーバー起動から1分は何もしない。GameTest では動かない。メッセージは一切出さない。
- 記録: 作ったチャンク（プレイヤーが通って読み込まれたものも）をアストリアのデータ `data/eternalrealm_pregen.dat` にビットで保存
  （地図の版が変わると捨てて調べ直す。あるチャンクは読むだけなのですぐ済む）。
- 管理者: `/eternalrealm pregen status`（作った数・割合・作っている数・平均tick）、`pause` / `resume`（そのセッションだけ）。
  恒久的には `performance.chunkPregen`。
- 注意: 先に作ったチャンクは作った時点の地形・建造物のまま（今も一度訪れた場所は同じ）。地形を変える更新では地図の版
  （`FieldLayout.VERSION`）を上げて作り直す。セーブは数百MB増える見込み。
- テスト: `ChunkPregenPlanTest`（範囲、輪の順で全チャンクを1回ずつ、作れなかったチャンクの再挑戦、プレイヤーの先の帯と向き、
  作ったもの・他人の視界・地図の外を除く、保存と別の版の拒否、チャンク番号の形式）。

- 生成ステップ: RAW_GENERATION=地表 → LAKES=池 → LOCAL_MODIFICATIONS=地割れ・尖塔・岩・結晶・噴気孔 → SURFACE_STRUCTURES=塔・遺跡・柱・畑・浮島 → … → VEGETAL_DECORATION=木・花・草 → TOP_LAYER=凍結。

## 3. フィールドの手作り建造物（Field set pieces）

風車・農家・港町・神殿跡・峠の関所などの**手作りの建造物（セットピース）**は、Python のビルダー（`tools/fields/`）が
本物のフィールド地形（純粋モジュール `FieldTerrain` を `tools/fields/TerrainProbe.java` で実行）の上に組み立てて書き出し、
`FieldChunkGenerator` がチャンク生成時にそのまま刻む。出力は決定的（同じ入力から同じバイト列）。

```
python3 tools/fields/build.py                        # 全ピースを組み立て → 書き出し → 検査（約10秒、地形はキャッシュ）
python3 tools/fields/build.py --previews             # + tools/fields/previews/ にプレビュー（遠近図・平面図・一覧・全体地図、約20分）
python3 tools/fields/build.py --only peaks_pass --previews   # 1ピースだけ（書き出さない。--export で書き出す）
```

- ピースは `tools/fields/pieces/` のモジュール（`build() -> list[Piece]`、ファイル名順）。部品は `kit.py`（整地・舗装・灯り・看板・旗・植物）、
  `build_kit.py`（家・納屋・風車・塔）、接続形状は `connect.py`（柵・板ガラス・塀・階段の形をバニラと同じ規則で事前計算）。
- **書き出し** `data/eternalrealm/fieldpieces/`: `manifest.json`（ピースごとのパレット、ブロックエンティティの SNBT、エンティティ、
  流体ティック、検査用プローブ、地形サンプル、転移碑）と `pieces/<id>.bin`（gzip、形式 ERP1: チャンク単位のタイル、列ごとのランレングス、
  パレット 0 = 地形のまま / 1 = 空気、列ごとの基礎ブロック）。87ピースで約 0.41 MiB（上限 8 MiB）。
- **検査** `tools/fields/check.py`（ビルドの最後に必ず実行）: 全デコード、パレットの正規形、BE の載る先、流体ティック、エンティティ、
  プローブ、王都から24以上（南門前の広場だけ8）、ダンジョンの門から20（終焉の塔30）と門の前（正面48×幅11）に背の高いものを置かない、
  フィールド名テストのチャンクに置かない、転移碑（下半分が `FieldLayout.waystones()` から3以内、上下2ブロック・向き・周囲2マスが歩ける・床）、
  ピース同士の食い違い、サイズ。
- **重なり**: 2つのピースが同じ列に書くと、順位の高い方がその列を取り、低い方は列ごと手を引く（転移碑の祠 > 橋・境界の門 > 道標 >
  建造物 > 道端の灯り・柵 > 花畑。同順位はビルド順）。柵の列は橋や祠の手前で止まる。

### Java 側

| クラス | 内容 |
|---|---|
| `world.field.FieldPieceData`（純粋） | 書き出しの読み込み（ERP1 のデコード、チャンク索引）、`covers(x, z)`、`near(x, z, r)`、`lowestBlock`、`ownsGround`、`waystoneNear` |

## 8. 既知の制限

- 地形はバニラのオーバーワールドノイズ。王都や入口が海・山に当たると、土台を埋め立て／切り崩して整地する（周囲は8〜12ブロックでなだらかに戻す）。
- 建物・看板の文字（Sign）は無い。掲示板の「紙」は旗で表現。NPC は統合側が配置する。
- 溶岩の川・池は流れ出さない位置にだけ置くが、プレイヤーが縁を壊すと流れる。浮島の滝は地面に落ちて広がる（通常の水）。
- 宝箱・樽は装飾のみ（中身なし）。
