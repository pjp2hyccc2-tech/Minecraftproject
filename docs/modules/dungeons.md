# ダンジョンの内装（`dungeon.decor` / `dungeon.forge.decor` / `client.DungeonAmbienceClient`）

ダンジョンの内装（オーナーの依頼: 遊びやすさはそのままに、テーマごとの建築・小物・灯り・雰囲気を作り込む）。名前・意匠はすべて独自。
レイアウト（`DungeonLayoutGenerator`、部屋・通路・扉・湧き位置・罠）は**一切変えずに**、その上にテーマごとの内装を重ねる。
明るく読みやすく、小物が多く、テーマがひと目で分かる手作り風のダンジョンにする。

## 1. 仕組み

| 層 | クラス | 役割 |
|---|---|---|
| 純粋 | `DungeonDecor` | レイアウト → `DecorPlan`（ブロック状態の文字列の列、追加で建てる箱、液体の箱、復活地点と向き）。決定的 |
| 純粋 | `Canvas` | 建築計画をボクセルに再生し、その上に内装を書く。予約（下記）と「書いてよい範囲」を守らせる。光の計算、歩ける経路の探索 |
| 純粋 | `Style` と9つのテーマ（`CityStyle` … `ThroneStyle`） | 共通の建築（壁の帯・付け柱・コーニス・扉枠・梁/ヴォールト・床のメダリオン・アーチ・前室・アリーナの縁・入口の広間）と、テーマ独自の小物・像・灯り・セットピース |
| 純粋 | `DecorBlocks` | 使うブロックの当たり判定（無し/薄い/部分/全体）・光の量・光を通すか・液体か |
| 純粋 | `DungeonAmbience` | テーマごとの漂う粒子と時々の環境音 |
| Forge | `forge.decor.DecorBuilder` | 計画を別スレッドで立て、建築計画のあとに1tick 4000ブロックずつ置く。片付けの前に液体を抜く |
| Forge | `DungeonInstance`（小さなフックのみ） | 建築計画 → 内装 → 開始。片付けは内装の追加の箱も。`revivalPoint()` / `revivalYaw()` |
| クライアント | `client.DungeonAmbienceClient` | 地図データ（`MapView.Dungeon`）でインスタンス内にいると分かったら、そのテーマの粒子と音を自分の周りにだけ出す |

- 内装は自分専用の乱数（レイアウトのシードから）で決まる。同じレイアウトなら同じ内装。レイアウトそのものは変わらない。
- ブロックは `#wall` のようなパレット役割（`DungeonPalette` で解決）か、コマンド書式の状態（`minecraft:lantern[hanging=true]`）。
  看板の文字だけはブロックエンティティのデータ（SNBT）を持つ。
- 形の更新なし（`UPDATE_CLIENTS | UPDATE_KNOWN_SHAPE`）で置く。柵・板ガラス・鉄格子・塀のつながりは計画側で計算済み。
  建てている途中にランタンや松明が落ちることはない。

## 2. ゲームプレイを変えないための規則（`Canvas` が強制）

- **書けない（HARD）**: 扉の開口部、その前の通り道（レーン、深さ4）、モンスターの湧き位置のまわり（x-1〜x+2、z-1〜z+2、高さ1〜5）、
  入口の到着地点、復活地点、セットピースへの入口とその前。
- **ぶつかる物は置けない（SOFT）**: 通路の通り道（幅3・高さ4。天井角のアーチの階段だけは高さ4の左右に置く）、**ボス部屋の空間全体**
  （旗のように当たり判定のない物だけ）。巨大ボスが歩く床と空間は何もない。
- **書いてよいのはレイアウトの箱と、内装が確保した箱だけ**。確保は他の部屋・通路・確保に触れると断られる。確保した箱は
  `DecorPlan.extraBoxes()` としてインスタンスの片付けに加わる。
- 床は別の満ブロックに置き換えるだけ（段差を作らない）。戦闘部屋の家具は壁ぞい（隅は2列まで）に置き、中央は空ける。
- 水と溶岩は四方と下を塞いだ所にだけ置く（流れない・燃え移らない）。片付けでは最初に液体だけを更新なしで消す。
- 価値のあるブロック（金・鉄・ダイヤ等のブロック、ビーコン、エンチャント台など）は使わない（ダンジョンのブロックは壊せるため）。
  金の山は蜂の巣ブロックと金の感圧板で表す。ボス部屋の床の縁の元の装飾（空の遺跡では金ブロック）もテーマの床材で覆う。

## 3. 共通の建築

- **戦闘部屋**: 壁の腰帯・フリーズ帯、5〜6ブロックごとの付け柱（柱頭の持ち送り、ひとつおきに壁灯）、扉枠と楣、天井のコーニス、
  梁（地下都市・古代樹）か、3段の入隅で3ブロック高くした格天井（神殿・氷の城・天空・塔・玉座）、床の縁取り・中央のメダリオン（中心と軸上に光る石）・
  扉からの敷石の道、ひび・苔などの傷み、壁ぞいの小物、四隅の小物、シャンデリア。ボス前の扉は二体の像と装飾の楣で飾る。
- **通路**: 4ブロックごとのアーチ（壁の付け柱・天井の帯・角の階段）、その間に「格子の奥の灯り」「壁に立つ像」「壁灯」「旗」が順に並ぶ。
  格子や像は壁の位置に入るので、通り道の幅は変わらない。床の中央に敷石の帯。
- **前室（ボス部屋の手前の通路）**: 両側と上を広げ、高いヴォールトの列柱の間にする。通り道は元の通路のまま（列柱の間は高さ1.5の手すりで閉じ、
  罠の効き方は変わらない）。側廊に像と火鉢、外壁に旗と灯、通路の上高くにシャンデリア。ボス部屋の壁の開口部に大きな門枠とテーマの彫刻。
- **ボス部屋**: 縁だけ。壁の腰帯・帯・付け柱、壁の奥の格子越しの火（溶岩の滝、魂の火など）、高い所の光る窓と縦に連ねた旗、
  床の縁取りと大きな紋章（輪・放射線・光る鋲）、天井の格子。床と空間には何も置かない。
- **入口の広間**: レイアウトの小さな広間（11×11）を扉の反対側と左右に広げる（パーティ: 奥へ6・左右へ4・高さ10、レイド: 奥へ9・左右へ6・高さ12。
  入らなければ段階的に小さく）。奥の壁に**出口の門**（枠と光る幕、飾り）、左に**復活の像**、右に**掲示板**（ダンジョン名・「掲示」・「最奥に主あり」の看板）、
  元の壁の線に列柱、入口の扉の枠と旗、到着地点の床にメダリオン。
- **復活地点**: 復活の像の正面（広間の内側へ3ブロック）の足元の位置。向きは入口の扉の方（ダンジョンの奥へ）。
  `DungeonInstance#revivalPoint()`（`BlockPos`、ワールド座標の足元）と `revivalYaw()`。計画ができる前は到着地点を返す。
  像のそばに「復活の像」の立て看板。
- **セットピース**: 戦闘部屋の、開口部のない壁の外に空きがあれば（13〜17四方、高さ10）、短い通路でつなぐ（ダンジョンごとに最大2、ボス前の部屋は最後の候補）。
  中身はテーマごと（下表）。戦闘の流れには関わらない（湧きは部屋の中、罠も無し）。

## 5. 光

- 戦闘部屋・通路・前室の通り道・ボス部屋・入口の広間・セットピースの、立てる床のすべてでブロックの明るさ **7以上**（`DungeonDecor.TARGET_LIGHT`）。
- まずテーマの灯り（壁灯・シャンデリア・床の光る石）。暗い所が残れば、その上にテーマのシャンデリアや吊り灯、ボス部屋では床の光る鋲を足す。
  それでも届かない所だけ、見えない光ブロック（`minecraft:light`、当たり判定なし）を真上か近くに置く。
- 光の計算は純粋側の近似（不透明な満ブロックで止まり、他は通す）。使うすべてのブロックの光量・遮光を GameTest で実際の値と照合している。

## 6. 雰囲気（粒子と音）

- クライアントだけで再生する（サーバーとネットワークの負担なし）。毎秒8〜14粒をプレイヤーの周り10ブロックに。粒子の設定に従う（最小で無し、減らすで半分）。
- 4〜20秒ごとに小さな環境音（音量0.3〜0.45、ピッチを揺らす）。
- ブロック自体も粒子を出す（焚き火の煙、蝋燭の炎、胞子の花、光の棒、溶岩のはね、泣く黒曜石のしずく）。

## 7. テスト

- `DungeonDecorTest`（純粋、全ダンジョン×3シード＋レイド）: 決定的、導いた開口部がレイアウトの扉と一致、扉・レーン・湧き位置・通路・ボス部屋の空間に物がない、
  戦闘空間の床がすべて明るさ7以上、入口からボス部屋・すべての湧き位置・復活地点・セットピースまで歩ける、復活地点が広間の中で扉を向く、
  置いた物がすべて片付けの範囲内・液体は塞がれて先に抜かれる、状態の書式・価値のあるブロックなし、テーマごとに25種以上の固有の語彙
  （どの2テーマも共通は35%未満）、雰囲気の定義。
- `DecorGameTests`（GameTest）: 計画のすべてのブロック状態が実際に存在し、当たり判定・光量・遮光・液体が純粋側の表と一致する。看板のデータが読める。
  雰囲気の粒子と音が登録されている。

## 8. プレビュー

`tools/dungeon-preview/preview.py <d1〜d8|final> [シード]`（先に `bash tools/offline-test.sh` で純粋モジュールをビルドしておく）。
`DumpDecor.java` で内装つきのボクセルを書き出し、王都の道具（`tools/capital/preview.py`）のレイトレーサーで、入口の広間・戦闘部屋・通路・前室・
セットピース・ボス部屋の目線の絵と、手前の壁と天井を外した見下ろし（ドールハウス）を `build/dungeon-previews/` に描く。
色はブロックの平均色の近似で、ゲームのテクスチャは使わない。

## 9. 未実装・未確認

- 実機（クライアント）での見た目・歩いた感触・重さは未確認（プレビューは近似の色）。
- 地図・ミニマップにはセットピースと広げた広間が出ない（`MapView.Dungeon` は部屋と通路のみ）。
- 到着時の向きは従来どおり北向き（`bringIn`）。広間の扉の方を向かせるなら `revivalYaw()` と同じ考え方で変えられる。
- ダンジョンのブロックはプレイヤーが壊せる（既存の仕様。内装に価値のあるブロックは使っていない）。
