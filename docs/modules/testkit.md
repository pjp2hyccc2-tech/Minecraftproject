# テスト用キット（test kit）: 最大化と見学用の屋敷

オーナーの依頼（2026-11-11）:「テスト用に、すべての部屋とギルドハウスの開放とお金をマックスとレベルとステータスポイント、
スキルポイントをマックスにするコマンドを実装して」

管理者（権限2）だけが使えるテスト用のコマンド。キャラクターを一度で最大にし、宿屋の客室5室とギルドハウス20軒を
**すべて見学できる** ようにする。どれもゲームと同じサービスを通すので、検証・保存・画面の更新は普通に遊んだときと同じ。

| 場所 | 内容 |
|---|---|
| `player.PlayerDataService#maxOut`（純粋） | レベルを上限へ、所持金を上限へ、ステータスとスキルのポイントをすべて戻す |
| `estate.Showcase`（純粋） | 見学用の屋敷のキー（持ち主 = 種類と間取りから決まる固定の id） |
| `estate.forge.Showcases` | 見学パス（プレイヤーの永続データ）、見学できる間取りの登録、建てる・入る・状況 |
| `estate.forge.EstateService#mayAccess` | 見学用の屋敷にはパスを持つ人（とクリエイティブの管理者）だけが入れる |
| `estate.forge.InnService` / `ui.estate.InnScreen` | 女将の画面の「見学」ボタン（パスを持つ人だけ） |
| `guild.house.forge.GuildGates` / `GuildHouseEvents` | パスを持つ人は門から見学用のハウスへ。見学用のハウスでは鐘は誰も呼ばず、金庫は開き、出し入れは記録しない |
| `testkit.TestKitCommands` | `/eternalrealm admin test ...`（`/er` でも同じ） |
| `testkit.bots.BotIds` / `BotPlans`（純粋） | テストボットの番号・id・名前・色、職業・ポイントの振り方・狩り場・買い物・戦う距離の決め方 |
| `testkit.bots.forge.*` | テストボット本体（`TestBot`・接続・頭脳・歩き方・戦い方・持ち物）と `/er admin bots ...`（§4） |
| `client.BotSkins` | テストボットを1体ずつ違う単色の姿で描く |

## 1. コマンド（権限2、プレイヤーを省くと自分）

| コマンド | 内容 |
|---|---|
| `/er admin test all [<プレイヤー>]` | 下の `max` と `unlock` を一度に |
| `/er admin test max [<プレイヤー>]` | Lv を上限（設定の `levelCap`、既定 100）に、所持金を上限（9,999,999,999 G）に。割り振り済みのステータスと習得済みのスキルはすべて戻し、上限の全ポイントが未使用になる（既定で ステータス 297・スキル 218）。スキルの装備欄は職業の初期に戻る。職業はそのまま |
| `/er admin test unlock [<プレイヤー>]` | すべての部屋とギルドハウスを開放: 見学パスを渡し、まだない見学用の建物（客室5・ギルドハウス20）を建てはじめる |
| `/er admin test lock [<プレイヤー>]` | 見学パスを取り上げる（見学中なら外へ出る）。建物はそのまま残る |
| `/er admin test tour <room\|guild> <間取り>` | どこからでもその見学用の建物へ（候補は Tab で出る）。まだなければ建てはじめ、進み具合を表示 |
| `/er admin test status` | 見学用の建物の完成数・建築中（%）・未着手、パスを持つオンラインのプレイヤー |

- `max` はレベルを直接上げるので、獲得 EXP（ランキング）は増えない（`/er admin level set` と同じ）。
- 権限のないプレイヤーには `admin` 以下が見えず、実行もできない。

## 2. 見学用の屋敷（showcase）

- 客室とギルドハウスは「1人1部屋」「1ギルド1軒」なので、自分の部屋やハウスとは別に、**間取りごとにもう1つ** 見学用の建物を
  屋敷の次元に建てる。持ち主は `UUID.nameUUIDFromBytes("eternalrealm:showcase/<種類>/<間取り>")`（`Showcase.owner`）: 再起動しても
  同じ建物が見つかり、プレイヤーやギルドの id（ランダム、またはプレイヤー名から作る id）と重なることはない。
- 建てる仕組み・区画・保護・保管・模様替えの照合は普通の屋敷とまったく同じ（[estates.md](estates.md)）。建築は1件ずつ順番に進むので、
  25件を全部建て終えるまで少しかかる（その間も建ち終えたものから入れる）。見学用の建物は取り壊さない。中にしまった物はそのまま残る。
- **入れる人**: 見学パスを持つ人と、クリエイティブの管理者（どの屋敷にも入れる）。パスを取り上げられた人は 0.5 秒ごとの見張りで外へ。
- **見学パス**: プレイヤー自身の永続データ（`eternalrealm_showcase_pass`）。プレイヤーと一緒に保存され、死んでも残る。
- **入り方**
  - 客室: 宿屋の女将の画面で部屋を選び「見学」（自分が借りている部屋とは別。準備中は「準備中 n%」）。または `tour room <間取り>`。
  - ギルドハウス: ギルド門の広場で、自分のギルドが持っていない間取りの門をくぐる → その見学用のハウスへ（まだなければ建てはじめ、
    進み具合を表示して押し戻す）。自分のギルドの間取りの門は今までどおり自分のハウスへ。または `tour guild <間取り>`。
  - 着くと「見学: <間取り>」の表示。出るときは部屋の扉のメニュー、ハウスの帰りの門（どちらも来た場所へ）。
- **見学用のハウスの中**: 掲示板は見ている人のギルドのもの（ギルドがなければ空）、集合の鐘は誰も呼ばない（その旨を表示）、
  金庫はパスを持つ人なら開く、チェストの出し入れは記録しない（どのギルドのものでもない）。案山子・作業台・噴水などはそのまま。

## 3. テスト

- 純粋: `ShowcaseTest`（25件それぞれ別の固定の持ち主、プレイヤーやギルドの id は見学用にならない、持ち主から間取りを引く、
  不正な名前）、`PlayerDataServiceTest#theTestKitMaxesTheCharacterOutWithEveryPointUnspent`（上限・所持金・全ポイント未使用・
  職業はそのまま・獲得 EXP は増えない・設定の上限が低いサーバー・保存）。
- GameTest `TestKitGameTests`: 本物のコマンド（`/er` の別名から）で権限なしは何も変わらず、権限2で最大化される。パスを持つ人は
  門で待たされたあと見学用のハウスに入り、帰りの門で出る。客室の見学、女将の画面の「見学」はパスを持つ人だけ、パスのない人は
  どこにも入れない、パスを取り上げると外に出される。

## 4. テストボット（AIプレイヤー）

オーナーの依頼（2026-11-12）:「複数人プレイをもしたテストを行うために、本物のプレイヤーと同じような行動を行うAIを30体導入して。
見た目はワンカラーのキャラでいい、テスト後消すから。」

**本物のプレイヤーとしてログインする** AI。サーバーのログイン処理をそのまま通る（プレイヤー一覧・参加メッセージ・キャラクターの
読み込み・保存・ログアウトまで普通のプレイヤーと同じ）。クライアントの代わりに頭脳（`BotBrain`）が入力を決め、移動は
プレイヤーと同じ物理（歩く・走る・段差を跳ぶ・扉を開ける）、攻撃・スキル・宿・店・パーティはクライアントが送るのと同じ
サーバーの処理を呼ぶ。だから検証・保存・ほかのプレイヤーへの表示は本物と同じで、混雑・パーティ・負荷を実際に試せる。

### コマンド（権限2、`/er` でも同じ）

| コマンド | 内容 |
|---|---|
| `/er admin bots spawn [<数>]` | Bot01〜Bot<数>（既定 30、最大 64）のうちいないものが 0.25 秒おきに1体ずつログインする |
| `/er admin bots remove` | 全員ログアウト。キャラクターは残り、次に `spawn` すると続きから |
| `/er admin bots purge` | ログアウトに加えて痕跡を片づける: 借りた宿の部屋を返し、ランキングの記録を消す |
| `/er admin bots list` | いるボットの Lv・職業・していること・場所 |
| `/er admin bots send <town\|shop\|inn\|hunt\|return>` | 全員にいますぐその行動をさせる |
| `/er admin bots chat <on\|off>` | ときどきチャットで話すかどうか（既定 on。1体あたり最短 6 分に1回） |

### ボットがすること

- **はじめて**: 職業案内人のところまで歩いて職業に就く。番号順に ナイト・アサシン・メイジ・レンジャー・プリースト・魔法剣士
  （30体なら各5体）。初期装備（武器と回復薬）は普通のプレイヤーと同じ。
- **街**: 次にすることを決める（`BotPlans.nextErrand`）。持ち物が埋まってきた・回復薬が少ない（買えるなら）→ 道具屋。狩りを
  2回したら → 宿で休憩。ときどき街の施設のどこかへぶらぶら歩いて辺りを見回す。それ以外は狩りへ。
- **道具屋**: 店の画面を開き、プレイヤーと同じクリックで素材を売り（持ち物が埋まってきたら使わない装備も）、その Lv で飲める
  いちばん良い回復薬を 8 本まで（所持金の半分まで）、帰還の巻物（なければ）、余裕があれば永久花の花びらを買う。
- **宿**: 女将のところへ行き、部屋があれば入って 30〜90 秒休む（中を少し歩く）。部屋がなく 1,500 G あれば屋根裏部屋を借りる
  （建つのを待って入る）。お金がなければロビーでひと休み。
- **狩り**: Lv に合う生息地（そこの魔物の Lv が自分の Lv−3〜+1 にかかるところ）を選び、いちばん近いウェイストーンへ
  移動してから歩いて向かう。着いたら生息地の中で魔物を探して戦い、いなければ中を歩き回る。4〜6分たつ・回復薬が尽きて体力が
  少ない・持ち物がいっぱい → 帰還の巻物（なければすぐに首都へ）。
- **パーティ**: 狩りに出るとき半分くらいの確率で、街にいる Lv の近い（±6）手の空いたボットを1〜3体誘う（招待と承諾は
  プレイヤーと同じ処理）。メンバーはリーダーの狩りについて行き、離れすぎたら追いつき、リーダーの敵か近くの魔物と戦い、
  リーダーが帰るとき一緒に帰る。倒れたメンバーには花びらを持っていれば駆け寄って使う。
- **戦い方**（`BotCombat`）: 敵を見て武器の届く距離まで寄る（弓と杖は 8 ブロック離れて撃ち、近づかれたら下がる）。弱攻撃を
  リズムよく、ときどき溜め攻撃、武器スキルと職業スキル（使えるようになったもの）を間をおいて、奥義は元気な強敵にだけ。体力が
  45% を切ったら回復薬、追い詰められたら回避。リクエストはクライアントの代わりにサーバーの戦闘処理へ送るので、クールダウン・
  スタミナ・Lv 制限は普通どおりかかる。
- **成長**: ステータスポイントは職業の伸び方に合わせて（VIT は少し多め）、スキルポイントは使えるスキルを装備欄が埋まるまで新しく
  覚え、そのあと覚えたものを上げる（全部覚えきるまで止まらないことを `BotPlansTest` で確かめている）。
- **倒れたとき**: 普通のプレイヤーと同じく倒れた状態になる。パーティなら 10 秒ほど助けを待ち、そのあと「帰還」を選ぶ。
  （アストリア以外の世界で死にそうになったときは、その場で立ち直って家へ帰る: ボットは「リスポーン」を押せないため。）
- **チャット**: 職業に就いたとき・狩りや買い物に出るとき・部屋を借りたとき・倒れたとき・仲間を起こすとき・レベルが上がったとき、
  ときどきひとこと。

### 見た目

- 1体ずつ違う単色（黄金角で色相を回し、彩度3段階×明るさ2段階: 30体のどの2体も見分けがつく色の差、`BotIdsTest`）。頭の上が少し
  明るく脚が暗く、目が2つ。外側のレイヤーは透明。名前は Bot01〜Bot64。
- クライアントが番号から決まる id でボットを見分け、プレイヤー一覧のその人の肌に、その場で描いた絵を入れる（`client.BotSkins`）。
  装備や職業の衣装は普通どおり重なる。

### 注意

- **重さ**: ボット1体ごとに周りのチャンクが読み込まれ、魔物が湧き、パケットが作られる（本物の30人と同じ）。シングルプレイでは
  パソコンの負荷がかなり上がるので、重いときは `spawn 10` などで数を減らす。
- **シングルプレイ**: 権限が要るので「チートの許可」をオンに（または LAN に公開してチートをオン）。ワールドを閉じるとボットも
  ログアウトし、次に開いたときは `spawn` し直す。
- **残るもの**: キャラクター（Lv・所持金・持ち物）とプレイヤーデータはワールドに残る（次回の続きのため）。ランキングにも
  載る。消すときは `purge`（宿の部屋とランキングの記録を片づける）。キャラクターのファイル自体は残る（小さい）。
- **しないこと**: ダンジョン・ボス・PvP・オークション・合成・強化・装備の付け替え（拾った装備は売る）・騎乗・クエスト・ギルド。
  必要になったら足す。

### テスト

- 純粋: `BotIdsTest`（64体の id・名前が重ならず固定、番号に戻せる、30体の色の差）、`BotPlansTest`（30体で各職業5体、ポイントの
  振り方、全職業のスキルツリーを1点ずつ最後まで覚えきる、Lv 1〜100 のどれにも狩り場がある、生息地ごとのウェイストーン、
  買い物、街での行動、戦う距離）。
- GameTest `TestBotGameTests`（専用のバッチ）: ボットが本物のログインで入り、プレイヤーの物理で歩いて（瞬間移動でなく一歩ずつ）
  アリーナを横切り、ログアウトする / 職業に就いて武器を持ち、戦闘処理へのリクエストで魔物に攻撃を当てる / 自由にさせたボット
  （狩りには出さない）が番号の職業に就いて街の用事をこなし、その間に一度もつまずかない。

## 決定事項（Decisions）

- **「開放」= すべての間取りに入れること**: 部屋とハウスは1人（1ギルド）1つの決まりなので、それを崩さずに全部を確かめられるよう、
  間取りごとの見学用の建物を別に建てる方式にした。自分の部屋やハウスはそのまま（所持金が上限なので、借りる・買う・模様替えも
  そのまま試せる）。
- **パスで入れる**（権限だけで入れない）: 管理者が普通にギルド門の広場を歩いても、パスがなければ門は今までどおり。テストのときだけ
  `unlock` で開き、`lock` で戻す。
- **持ち主は固定の id**: 見学用の建物を覚えておく表がいらず、何度 `unlock` しても同じ建物を使う。
- **ポイントの最大 = 上限レベルで得る全ポイントを未使用に**: 割り振りを戻すので、テストのたびに自由に振り直せる。上限を超えるポイントは
  作らない（ゲームの決まりのまま試す）。
- **テストボットは本物のプレイヤー**（偽のエンティティでなく）: サーバーのログイン・保存・プレイヤー一覧・パケット送信まで本物と
  同じ道を通すことで、30人いるときの重さや、パーティ・宿・店・ランキングが人数に耐えるかをそのまま確かめられる。接続は送った
  パケットを捨てる仮のものだけで、ほかはゲームのコードを使う。
- **ボットは自分の入力で動く**: 瞬間移動で済ませず、経路を探して歩く（6 秒進めないときだけプレイヤーの「移動」と同じく
  目的地へ）。混雑・扉・段差で引っかかる所も本物に近い形で見える。
- **見た目はクライアントで描く単色**: 依頼どおりワンカラー。絵はその場で描くので、配布する画像はない。
