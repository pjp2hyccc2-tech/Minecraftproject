# HUD（画面表示）

オーナーの依頼（2026-11-10）: 「あらゆるHUD同士が被って邪魔なので修正」「マインクラフト本来のホットバーを削除」「画面右側にカバンマークと装備マーク
（各アイコンの右下にボタンヒント付き）」。

## 配置（`hud.HudLayout`、純粋・テストあり）

毎フレーム、画面の大きさと「いま出ているもの」（パーティー人数、ボス戦、状態効果の数、会話ボックス、脅威ゲージ、字幕の有無、チャットの
幅と高さ）から全パーツの矩形を計算し（`ui.hud.HudFrame`、`RenderGuiEvent.Pre`）、各オーバーレイはその矩形の中だけに描く。

| 場所 | パーツ |
|---|---|
| 左上 | 自分の枠（Lv・名前（職業色）・EXP%・HPバーと数値・水中の息・未使用ポイント）、その下に状態効果アイコン（最大2段）、その下にパーティー枠 |
| 上中央 | ボスHUD（左右の列の間。狭い画面では最上段に置き、左右の列を下げる）、その下に会話ボックス（バニラのタイトル文字より上） |
| 右上 | ミニマップ、地名・道案内の行（「▶ 森の賢者と話す 238m」）・座標、脅威ゲージ、ヌシ討伐の結果カード、ボスの戦功ランキング、拾得表示の場所（`pickupFeed`） |
| 下中央 | 武器スキル（名前つき）・職業スキル6枠（必殺技は少し離して金枠）・クイック使用3枠 |
| 右下 | 装備アイコン（上）とカバンアイコン（下）。キーはアイコンの右下。装備アイコンの左に乗り物アイコン（乗り物を持っていれば。`mount`、[mounts.md](mounts.md)） |

- 規則: 自分たちのパーツ同士は**どの画面でも重ならない**。幅427以上（1280×720のGUI倍率3など）ではバニラのチャット（未フォーカス時の
  最大範囲）とアクションバーにも重ならない。右列の文字ブロックはチャットやアクションバーに届く行では幅を縮め、パーティー枠は
  通常行→詰めた行→2列の順に縮み、それでも入らない分は省く。ランキングは拾得表示に最低2行を残す。テスト `HudLayoutTest` は
  15種の画面サイズ×各4000通りの組み合わせで確認する。
- バニラの非表示（`ui.hud.VanillaHud`）: ホットバー・ハート・防具・息・経験値バー・選択中アイテム名・状態効果アイコン（自分の枠に統合）。
  満腹度は常に非表示（空腹なし、D-VITALS）。クリエイティブとスペクテイター、またはクライアント設定 `hud.enabled=false` ではバニラ表示に戻る。

## ミニマップの町の人（王都の中）

オーナーの依頼（2026-11-11）「王国内に入るとミニマップにNPCのいる場所に何のNPCかわかるように表示を出して」。

- 王都の中（`FieldLayout.inCapital`）では、ミニマップの町の人の点の代わりに **役目のアイコン**（12ピクセル、
  `textures/gui/map/npc_icons.png`、`tools/art/map_npc_icons.py` で描く）と **ラベル** を出す: 依頼受付（掲示板）・ギルド登録（羽ペン）・
  道具屋（薬瓶）・鍛冶屋（金床）・職業ギルド（つるはし）・取引所（木槌と金貨）・郵便局（封筒）・迷宮管理局（鍵）・闘技場（交差した剣）・
  栄誉の殿堂（トロフィー）・厩舎（蹄鉄）。物語の人物は吹き出しのアイコンと本人の名前。依頼の印（！／？）はアイコンの上。
- ラベルは近い順に最大8つ、0.75倍の文字に暗い下地。前のラベルと重なるもの・ミニマップの外にはみ出すものは出さない
  （`world.map.NpcMarkers.place`、純粋）。王都の外では今までどおりの点。
- データは今までの地図の文書（`MapView.Npc` の役目と名前、96ブロック以内の64人まで）。通信の変更なし。
- テスト: `NpcMarkersTest`（役目ごとのアイコンとラベル、アイコン画像の並び、ラベルの重なりと範囲）、`FieldMapTranslationsTest`（文言）。

（`ui.settings.SettingsAccess`）。翻訳は `docs/i18n/settings.json`。

## 転移門（`ui.gate.GatekeeperScreen`）

2026-11-13 のオーナーの依頼「ダンジョンの選択画面のHUDをファンタジーなものに変更して、マイクラ本来のままだから味気ない」。
門番に話しかけると開く（中身と規則は [boss.md](boss.md) §4「門番の画面」）。420×248（小さな窓では全体を縮める）。

- 枠: 夜空色の地に金の二重線（光が一周する）、四隅に宝石付きの金の飾り、題の赤いリボン「転移門」。地には星がまたたき、
  金の魔法陣が2つ逆向きにゆっくり回り、金の粒が昇る。上の左に討伐数（月桂冠）、右にソロ／パーティの人数とリーダーか。
- 左: 8つのダンジョンと区切りの飾りの下に最終レイド。行ごとに金のメダルの紋章（灯籠・樹・ピラミッド・鍵・雪の結晶・炎・羽根・
  塔・冠。封印中は錠前）、名前、推奨Lv（自分のLv＋3より上なら橙）か「封印中」、討伐済みなら月桂冠。選んだ行は金に光り、
  矢印が揺れる。
- 右: そのダンジョンの絵（9枚。ゆっくり流れる。切り替えは重ねて溶かす。テーマの粒子: 塵・ほたる・砂・霜・雪・火の粉・光・
  紫の火花が絵の上を漂う。封印中は暗くして鎖と錠前）、絵の下に地域と大きな名前、左上にLvの札、右上に月桂冠。その下にボス、
  人数・制限時間・部屋数、ダンジョンを語る2〜3行（封印中は先に「〇〇を倒すと封印が解ける」）、難易度の宝石3つ（ノーマル 緑・
  ハード 赤・EX 紫。選んだものは光る）、選んだ難易度のボスの倍率と報酬、自己ベスト、赤い「出発する」ボタン（出られないときは
  灰色で理由。カーソルを当てると説明）。
- 操作: クリック、↑↓（W/S）で選ぶ・ホイール、←→（A/D）で難易度、Enter／スペースで出発、Esc／インベントリキーで閉じる。
  選んだ難易度は次に開いたときも残る。ゲームは止めない（下準備が進む）。音: ページをめくる音、難易度の鈴、出発の音。
- 素材は `tools/art/gate_screen.py`（`textures/gui/gate/`、[ART.md](../ART.md)）。

## 出発の準備（`ui.gate.ReadyCheckScreen` / `ReadyCheckOverlay`）

2026-11-13 のオーナーの依頼「パーティーでダンジョンに入る時にメンバーの準備ができてるかのボタンを置いて欲しい 準備中、準備OK
って感じで」。パーティのリーダーが転移門で出発すると、全員に開く（中身と規則は [boss.md](boss.md) §4「出発の準備」）。

- 画面（300幅、人数で高さが変わる。小さな窓では縮む）: 転移門と同じ夜空の地と金の枠、リボン「出発の準備」、ダンジョンの絵の帯に
  名前と難易度の宝石、「準備OK 2/4」と残り時間（20秒を切ると橙）、メンバーの行（リーダーに冠、自分の行は金の縁、右に緑の
  「✓準備OK」か橙の「…準備中」）。下に大きなボタン: 自分が準備中なら緑の「準備OK」、準備OKなら琥珀の「準備中に戻す」
  （Enter／スペースでも）。リーダーには「中止」。全員そろうと「全員そろった！ 出発まで 3」が脈打つ。6人以上は2列（レイドの20人まで）。
- 閉じても続く（Esc・インベントリキー）。HUD の上の中央（ボスの体力バーがあればその下）に小さな枠: ダンジョンと難易度、全員の
  ✓／…と名前、自分の状態と答え方、残り時間か秒読み。終わると数秒だけ結果（「出発！」か中止の理由）。パーティの枠の名前の右にも
  各メンバーの✓／…。
- 音: 呼びかけのベル、だれかが準備OKになるたびの音、秒読みの始まりの鐘、出発の音、中止の低い音。
- ほかの画面を開いている人には自動で開かない（チャットの［画面を開く］か `/dungeon ready open`）。

## チャット（`ui.chat.FantasyChat`・`hud.ChatPanel`・`client.chat.ChatLog`）

2026-11-13 のオーナーの依頼「チャットの表示を邪魔にならない場所に小さく表示してそれもファンタジー風のHUDと枠を作って」。

- **入力していないとき**: バニラのチャットの代わりに、左下（バニラのチャットと同じ下端、画面の下から 40）の小さな枠に最新の
  メッセージを出す。幅は画面幅の 36%（170〜240）、文字はバニラの 0.85 倍、行数は設定ファイルの `[chat] lines`（2〜10、既定 5）。
  中身に合わせて高さが縮み、最後のメッセージから 10 秒で消える（最後の 1 秒で薄れる。バニラと同じ）。何も来ていなければ何も
  出ない。夜空色の半透明の地に金の帯の枠、四隅にサファイア、上の辺の中央に宝石の紋章。プレイヤーの普通の発言は「名前: 本文」
  （名前は金色。チームの色があればその色）。チャットの不透明度（バニラの設定）に従い、チャットを「非表示」にすれば出ない。
- **入力中**: バニラのチャットそのもの（スクロール・リンクのクリック・ホバーはいつも通り）を、同じ金の枠で囲む（1ページ分の
  大きさ、地は夜空色）。入力欄も金の枠（両端にサファイアの留め金）と夜空色の地。
- **HUD の配置**: 小さな枠の大きさ（いちばん多い行数と紋章の分）だけを空けるので、ほかの HUD はバニラのチャットのときより
  下まで使える（`HudFrame`）。
- 中身は Forge のチャット受信イベントで受け取ったもの（サーバーからのプレイヤーの発言・ゲームの知らせ・コマンドの結果。
  アクションバーは除く）と、このゲームがクライアントで出す知らせ（キーの重なりの移動など）。会話のログ（会話を読み終えたあと
  チャットに書く読み返し用の行）は入力中の一覧にだけ入り、小さな枠には出さない（読んだばかりなので）。ほかの MOD がクライアント
  の中で直接チャット欄に書いた行も、入力中の一覧にだけ出る。
- 設定画面「ファンタジー風のチャット」（`chat.fantasyChat`、既定オン）でバニラのチャットに戻せる。描画エラーが出たら自動で
  バニラのチャットに戻る（ログに記録）。
- 素材は `tools/art/chat_frame.py`（`textures/gui/chat/frame.png`、[ART.md](../ART.md)）。テスト `ChatPanelTest`（幅・高さ・
  折り返し・10秒と薄れ方・下から新しい順・長いメッセージは最後の行・古いものは出ない）。

## 操作

- **手に持つのは常にインベントリの1枠目（装備中の武器）**。数字キーとホイールでは持ち替えない。ドロップキーで武器を捨てない
  （`client.HudInput`）。サーバーはログイン時と最初の職業選択時に、1枠目に武器がなければ職業の武器（なければ何かの武器）を移す
  （`item.forge.MainHand.ensureWeapon`）。装備は `MainHand.equip`（その武器を1枠目と入れ替え）。
- **クイック使用**（バニラのホットバーキー 1〜3、`client.QuickSlots`）: 1 = 回復薬（足りないHPを VIT 補正込みで満たす一番小さいもの、
  なければ使える一番大きいもの）、2 = スタミナトニック、3 = 帰還の巻物。クライアントはインベントリの枠番号だけを送り
  （`UseItemPacket`）、サーバーが確認して使う（`QuickUse.useSlot` → `ConsumableItem.useFromInventory`。レベル・クールダウンは手で使う場合と同じ）。
  帰還の巻物はサーバー側で詠唱（`ReturnChannel`: 5秒、0.6ブロック以上動くか攻撃を受けると中断、成功時だけ1枚消費）。
- **カバン（E）と装備（C）**: `client.ClientScreens.openBag()` / `openEquipment()`。専用画面が入るまでは、カバン＝バニラのインベントリ、
  装備＝冒険手帳。`setBagScreen` / `setEquipmentScreen` で専用画面を入れると、バニラのインベントリ（E）もカバン画面に置き換わる。
- **カバン画面**（`ui.screen.BagScreen`、E）: カバン＝インベントリの2〜36枠目（35枠、1枠目は装備中の武器）。タブ 全て／装備／消耗品／素材／その他
  （全てはすべての枠をその位置に、他のタブは該当アイテムを詰めて表示）、レア度の枠と個数、選んだアイテムの説明（ツールチップと同じ行）、
  「使う」（消耗品: `UseItemPacket`）・「装備する」（装備）・「捨てる」（確認つき）・「整理」、使用量 n/35、所持ゴールド。右クリックで使う／装備する。
- **装備画面**（`ui.screen.EquipmentScreen`、C）: キャラクターの周りに8枠（左に頭・胴・脚・足、右に武器・アクセサリー2つ・お守り。
  装身具は [armory.md](armory.md)）。枠を選ぶと、カバンにあるその部位の装備
  （使えるもの優先、レベル順）と、装備中と比べた差分（攻撃力・防御力・最大HP・6ステータス・会心率・会心ダメージ・攻撃速度・移動速度、上がる値は緑▲・下がる値は赤▼）。
  レベル不足・職業で使えない武器・同じ装身具の二重装備は理由を表示し、装備ボタンを押せない。「外す」はカバンの最初の空き枠へ。下に装備全体の合計。
  金枠の遺宝は枠と候補一覧が金色の枠（カバンのマス・ツールチップ・取得表示も同じ）。
- **サーバー側**（`item.forge.BagService`、UIアクション）: `bag.equip {slot, target?}`（武器は `MainHand.equip` で1枠目と入れ替え、防具はその部位と入れ替え、
  装身具は `target` の枠か空いている枠へ。レベル・職業の武器・同じ装身具の二重装備を確認）、`bag.unequip {target}`（カバンが満杯なら断る）、`bag.sort`（同じアイテムをまとめ、装備→消耗品→素材→その他、
  レア度・レベルの高い順）、`bag.discard {slot}`。枠番号の範囲外は違反。並べ順・タブ・比較は純粋側の `item.bag`（`Bag`, `BagTab`,
  `EquipmentComparison`、テストあり）。
- **入手**（`item.forge.Bags`）: 魔物のドロップ（倒した本人の分）と、ヌシ・災厄・ダンジョン・クエスト・店などの報酬（`Inventories.give`）は
  直接カバンへ入る（同じアイテムの束に足してから空き枠へ。1枠目には入れない）。入りきらない分は足元に落ち、本人だけが拾える。
- **取得表示**（`ui.hud.PickupFeedOverlay`、`HudLayout.pickupFeed` の場所）: 入手のたびに1行（アイコン、レア度の色の名前、×個数）。
  同じアイテムが3秒以内に続けば同じ行に足す（`item.bag.PickupFeed`）。5秒表示して1秒で消える、最大5行で新しいものが下（アイコンのすぐ上）。
  レア以上は枠つきで効果音、カバンが満杯で足元に落ちた分は警告の行。地面から拾ったアイテムも表示する（`PlayerEvent.ItemPickupEvent`）。戦利品（魔物・ボス・ダンジョンの報酬）としてカバンに入った分は、クエストの「集める」目的にも数える（`Bags.loot`。2026-11-14 修正）。
- **バニラのアイテムは落ちない**（`item.forge.VanillaDrops`、2026-11-14）: アストリアとダンジョンでは、誰の名前もついていない
  バニラ（`minecraft:`）のアイテムは地面に現れない（戦闘で散った花びら・種・花・作物・枝が勝手に拾われてカバンが埋まっていた）。
  すでに落ちていた分はチャンクの読み込み時に消える。残すもの: プレイヤーが捨てた・落とした物（Q・画面の外へドラッグ・満杯で押し出された物）、
  カバンに入りきらなかった戦利品（持ち主つき）、倒れたプレイヤーの落とし物、プレイヤーが壊した箱・樽・かまどなどの中身（`item.KeepZones`）。
  ゲーム独自のアイテムには触れない。自室・ギルドハウスはバニラのまま。
  サーバーは `PickupFeedPacket`（プロトコル7）で本人にだけ送る。
- キーの衝突整理（`KeyConflicts`）: バニラの「ホットバー保存（C）」は装備キーと重なるため外す。ミニマップ切替は以前 N（職業スキル5と同じ）
  だったので Y に移す（プレイヤーが自分で変えた割り当てはそのまま）。
