# 王都アルセリア — capital voxel build (`tools/capital/`)

The new royal capital is generated by Python (numpy) and exported as binary tiles that the Java loader places
around the capital origin. Everything is deterministic: the same sources give byte-identical output.

```
python3 tools/capital/build.py                     # build + export + check (≈10 s)
python3 tools/capital/build.py --previews          # + every preview in tools/capital/previews/
python3 tools/capital/build.py --views plaza_north,great_hall --scale 0.5   # selected previews, half size
python3 tools/capital/check.py                     # re-validate the exported files
```

Output: `src/main/resources/data/eternalrealm/capital/manifest.json` + `tiles/<tx>_<tz>.bin`.

## 1. Coordinates and footprint

- Capital-local coordinates: **x east, z south, y up**; local y = world y − groundY. The plaza floor block top is
  y = 0 (players stand at y = 1), plaza centre (0, 0, 0). North (−z) is the castle.
- Box: x ∈ [−176, 175], z ∈ [−208, 175], y ∈ [−32, 159]. The footprint mask is that box with rounded corners
  (radius 40, `layout.footprint_mask()`); columns outside it are void.
- Columns are written from the foundation (`terrain.FOUND_Y` = −6, deeper under water) to y = 159 (air above
  the terrain clears the old town). Below the foundation the columns are **void** (natural stone is kept).
- The outer 16 blocks stay at y = 0 (meadow, fields, roads); the loader blends natural terrain outside.

## 3. API for district builders

```python
from capital import blocks as B, shapes, deco
from capital.world import Frame

DISTRICT = "market"                       # a name from layout.DISTRICTS

def build(w, district, terrain):          # called by build.py inside w.district_clip(district)
    x0, z0, x1, z1 = district.bbox()
    f = Frame(w, origin=(x0 + 5, 0, z0 + 5), rot=1)     # local +z (south) now points west
    shapes.hollow_box(f, 0, 1, 0, 8, 6, 10, B.full("white_plaster"), floor=False, ceiling=False)
    shapes.gable_roof(f, 0, 0, 8, 10, 7, "pale_roof_tiles", axis="z", gable_state=B.full("white_plaster"))
    deco.kingdom_wall_banner(f, 4, 5, 11, facing="south")   # facing is rotated with the frame
    w.spot("npc.item_shop", (x0 + 9, 1, z0 + 9), 180.0)
```

- See `districts/_template.py`. Modules run in file-name order; every write is clipped to the district region,
  dropped writes are counted (`w.clipped_writes`) and logged.
- **World** (all coordinates inclusive, any corner order): `idx(state)`, `set(x,y,z,state, only_empty=False)`,
  `get(x,y,z)`, `is_empty`, `fill(x0,y0,z0,x1,y1,z1,state, only_empty=False, replace=None)`, `fill_if_empty`,
  `replace(box, old_states, new)`, `clear(box)`, `set_many(xs,ys,zs,state)` (numpy arrays), `top_y(x,z)`,
  `heightmap()`, `be(x,y,z,snbt)` (block-entity data, no `id`/`x`/`y`/`z` keys), `entity(type,pos,yaw,nbt)`,
  `fluid_tick(x,y,z)`, `spot(name,pos,yaw)`, `clip(...)` / `district_clip(d)` context managers.
- **Frame(world, origin, rot, mirror)**: same write methods in local coordinates. Local x/z are mirrored
  (east↔west) if `mirror`, then rotated `rot` quarter turns clockwise seen from above (rot=1: local south →
  world west, local east → world south), then translated. States (`facing`, `axis`, `rotation` 0–15, stair
  `shape`, door `hinge`, vine sides) and entity yaws are transformed. `frame.sub(origin, rot)` nests;
  `frame.dir("north")` gives the world direction.
- **States**: `B.S("oak_door", facing="north", half="upper")` validates any state; helpers `B.full(mat)`,
  `B.stairs(mat, facing, half, shape)`, `B.slab(mat, type)`, `B.wall(mat)`, `B.log(wood, axis)`, `B.pillar()`,
  `B.leaves(kind)` (persistent), `B.pane(color)`, `B.glass(color)`, `B.trapdoor`, `B.carpet`, `B.lantern(hanging)`,
  `B.candle(n, color)` (lit), `B.chain`, `B.torch(facing)`, `B.banner`, `B.wall_banner`, `B.sign`, `B.wall_sign`,
  `B.hanging_sign`, `B.lectern`, `B.chest`, `B.barrel`, `B.potted(plant)`, `B.door_states(...)` → (lower, upper),
  `B.bed_states(color, facing)` → (foot, head; the head lies towards `facing`), `B.light_shaft(facing)`.
  Materials with stairs/slabs/walls: `castle_bricks`, `smooth_castle_stone`, `royal_roof_tiles`,
  `pale_roof_tiles`, `gilded_trim`, `terracotta_roof_tiles` (red clay roofs), `cobbled_paving` (street cobbles),
  `plaza_flagstones` (large pale flags), every vanilla stone family and wood (see `blocks.MATERIALS`; aliases
  `castle`, `roof`, `pale_roof`, `gold`). Windows: `leaded_glass` / `leaded_glass_pane` (diamond lattice,
  translucent). `castle_bricks`, `smooth_castle_stone` and `white_plaster` pick one of three textures at random per
  block (weathered variants), so large walls do not look printed. Stair `facing` = the side of the tall back (roof slopes face the ridge).
- **SNBT**: `B.KINGDOM_BANNER` (`{Patterns:[{Pattern:"er_crest",Color:4},{Pattern:"bo",Color:4}]}`),
  `B.banner_nbt([(code, color), ...])`, `B.sign_nbt(lines, color, glowing)` (1.20.1 `front_text`/`back_text`),
  `B.light_shaft_nbt(length, width, height, pitch)`, `B.lectern_nbt(title, author, pages)`, `B.item_snbt(id)`.
- The validator rejects unknown ids, properties and values. Connection properties (fence/pane/wall sides,
  stair corner shapes next to other stairs) are recomputed by the loader and are never written.
- **Lighting**: interiors should be moderately dark (chandeliers, candles, lanterns). Put
  `deco.light_shaft(t, x, y, z, facing, length, width, height, pitch)` just inside important windows: the beam
  travels towards `facing` (east windows → `west`), tilted down by `pitch`. The sun moves east→west through the
  zenith, so shafts come through east/west windows and skylights only.

**Interiors (`_furnish.py`).** The owner found the interiors too plain (2026-11-11). `dress(t, x0, z0, x1, z1, y,
ceiling, …)` dresses a room: exposed beams under the ceiling, a rug, plants in the corners, a lantern and paintings
on free wall spans (cells next to doors and the `keep` set stay clear). Single pieces: `painting`, `wainscot`,
`beams`, `rug`, `goods` (small wares on tables), `cupboard`, `wardrobe`, `nightstand`, `desk`, `kitchen`,
`bed_pair`, `plants`, `crates`, `item_on_wall`, `stair_up` (a straight stair whose last step is level with the
floor above, with its stairwell cut in that floor: two free blocks over every step and a third over all but the
last, because a 1.8-tall player stepping onto the next stair is still partly over this one). Ceiling beams never
go over a stair or ladder (`over_stairway`), so build stairs before dressing a room. Every half-timbered house gets a kitchen corner, a cupboard, a table with chairs, a rug, and upstairs beds
with nightstands, a wardrobe and paintings; the shops, the job hall, Gant's office, the hall of fame, the auction
house, the tavern and the inn are dressed room by room, and the item shop, the post office, the job hall and Gant's
office have furnished upper floors reached by a stair. A painting only hangs where every block behind it is a full
solid block and the blocks it covers are free (the game takes paintings down otherwise); `painting()` returns
False instead of hanging one that would fall. Beds lie fully inside their rooms (no headboards in the walls).

## 6. Export format (format 1)

`manifest.json`: `{"format":1, "build":"<hash>", "tileSize":32, "minY":-32, "maxY":159, "palette":[...],
"tiles":[{"x":tx,"z":tz,"file":"tiles/<tx>_<tz>.bin"}], "blockEntities":[{"pos":[x,y,z],"nbt":"<SNBT>"}],
"entities":[{"type":..., "pos":[x,y,z], "yaw":..., "nbt":"<SNBT>"}], "fluidTicks":[[x,y,z]],
"spots":{"name":{"pos":[x,y,z],"yaw":...}}, "blend":{"edgeY":0}}`.

- Palette index 0 = `eternalrealm:void` (do not touch), 1 = `minecraft:air`; the other states are canonical
  (properties sorted). Unused states are dropped at export.
- Tile (tx, tz) covers x ∈ [32·tx, 32·tx+31], z ∈ [32·tz, 32·tz+31]: `ERT1`, int32be tx, int32be tz, then
  32×32 columns x-major; each column = varint run count, then (varint length, varint palette index) pairs from
  minY up covering 192 blocks. All-void tiles are omitted.
- Block-entity SNBT holds only the data (`Patterns`, `front_text`, `Length`…), no `id`/`x`/`y`/`z`: the loader
  creates the block entity from the placed block and loads the data into it.
- Entities: `pos` is the entity position in local coordinates (feet for armour stands; the centre of the
  occupied block for item frames, whose NBT carries `Facing`); `yaw` is applied after loading the NBT.
  Armour stands are `Invulnerable` with all slots locked; item frames are `Fixed`.
- `fluidTicks`: water blocks that should be ticked once after placement (waterfall heads). Falling water is
  placed pre-settled (level 8 columns, level 1 spill), lakes and the river are still source water.
- Spot positions are feet positions; yaw: 0 = south, 90 = west, 180 = north, −90 = east.

## 7. Checks and budgets

`check.py` decodes every tile and checks: canonical/valid palette states, palette indices, void outside the
footprint, block entities sit on blocks that carry them, armour stands not inside solid blocks, fluid ticks on
water, all required spots present with a floor and free head room, non-air blocks < 4 000 000, tile bytes < 6 MB.
Paintings: a known variant, every covered block free, a full solid block behind each of them; no two hanging
entities (paintings, item frames) share a block. Staircases (runs of three or more bottom stairs, roof tiles aside):
each must start from a floor (not a lone block that needs a jump), have the head room above, end level with a
floor ahead of or beside the last step, and rise towards the stairs' `facing`; side-by-side runs are judged as one
wide stair. The owner found stairs facing the wrong way and stairs that could not be climbed (2026-11-11): the Star
Gate stair (reversed, a step short, a balustrade across its top), the guild gallery stair (a jump at both ends), the
market hall stair (into a pier, a gap at the top), the tavern and post office stairs (a gap at the top); all fixed.
