# ランキングシステム設計（Phase 6・未実装）

> 状態: 設計案。Phase 1 では、レベルランキングに使う `totalExperience`（シーズン累計EXP）の記録のみ実装済み。

## 1. カテゴリ（2.0）

総合／レベル／戦闘／探索／ボス討伐／生産／ギルド／パーティー／ボスタイムアタック（難易度別）。
企画書の個人・パーティー・ギルド別の細目（実績、PvP等）はカテゴリ定義ファイルで追加できるようにする。

## 2. 集計の原則

- **すべてサーバー側で集計**。クライアントから送られたポイントは受け付けない（そもそもそのようなパケットを作らない）。
- ポイントは「スコアイベント」として記録する: `(season_id, subject, category, amount, source, idempotency_key, occurred_at)`。
  同じ出来事（例: 同じボス討伐ID）からの二重加算は `idempotency_key` の一意制約で防ぐ。
- 集計方法（重み・上限・減衰）は**設定ファイル**で調整可能（2.0）。変更時は再集計できるよう、イベントから再計算可能な形にする。
- 役割評価（企画書）: タンク＝軽減・ヘイト維持、ヒーラー＝回復・蘇生補助、アタッカー＝有効ダメージ、探索＝発見・踏破、生産＝クラフト・納品。
- 総合ランキングは各カテゴリのスコアを正規化（例: カテゴリ内パーセンタイル）して重み付き合計。

## 3. ボスタイムアタック（2.0）

| 記録項目 | 取得方法 |
|---|---|
| 開始時刻 | サーバーがボス戦開始（戦闘エリア封鎖/初撃）を記録 |
| 撃破時刻 | サーバーがボス死亡処理で記録 |
| パーティー構成 | 開始時点の参加者UUID・職業・レベル |
| 難易度 | インスタンス生成時の設定 |
| 検証用データ | 参加者の位置ログ要約、与ダメージ合計、ボスHP推移のハッシュ |

不正検知: 理論最短時間を下回る記録、参加者がエリア外にいた記録、ボスHPの不自然な推移を自動で「保留」にし、管理者が確認する。

## 4. 不正対策

同一行動の無限反復（同じMobの繰り返し・放置狩り）への逓減、談合（同じ相手との繰り返し対戦）の検知、
記録の偽装はサーバー記録のみ採用することで防止。管理者用の取り消しは監査ログに残す。

## 5. 報酬と表示

報酬は称号・スキン・武器外見・エフェクト・ペット外見・記念像・ギルドエンブレム・歴代掲載など**性能差のないもの**に限定。
表示: ゲーム内UI、街のランキング掲示板、専用NPC。確定済みランキングはシーズンごとに `ranking_snapshots` へ保存し、現在のランキングと混同しない。
