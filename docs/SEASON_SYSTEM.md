# シーズンシステム設計（Phase 10・未実装）

> 状態: 設計案。実装済みなのは **season_id によるデータ分離のみ**（Phase 1）。

## 1. 2.0 での方針

- 14日間の攻略期間を1シーズンとして扱える構造にする。
- 攻略進行は DAY 1〜14 を目安にするが、**実時間で強制的に待たせない**。早く攻略すれば先へ進める。
- 終了時にランキングを確定し、過去の記録を保存する。
- 永続データとシーズン限定データを分離する。
- 次シーズン移行時にレベル・装備をリセットするかは設定で選ぶ。

## 2. 現在の実装（Phase 1）

- `season.currentSeasonId`（既定 `s1`、再起動で反映）
- キャラクターは `seasons/<seasonId>/characters/` に保存。シーズンIDを変えると新しいシーズンのキャラクターが作られ、旧シーズンのデータはそのまま残る。
- アカウント（永続データ）はシーズン外に保存。

## 3. 状態

`PREPARATION → ACTIVE → FINAL_BATTLE → RESULTS → RESETTING → COMPLETED`。基準はサーバーの信頼できる絶対時刻（ゲーム内時間ではない）。

## 4. 進行と解放（D-003, D-004）

| 層 | 内容 | 例 |
|---|---|---|
| ワールド解放（サーバー共通） | 条件を満たすとサーバー全体に解放 | 森林ボスがサーバーで初めて討伐されたら砂漠が全員に解放 |
| 個人条件 | 推奨レベル・前提クエスト | 砂漠入場は Lv15 以上推奨、メインクエスト3章クリア |
| 時刻ゲート（任意・既定OFF） | 最速解放日時 | DAY 7 より前には火山を開けない（運営判断で使う場合のみ） |

解放条件はデータファイルで定義する（地域ID・条件種別・値）。解放状態は `season_world_state` に記録し、再起動後も維持する。
後発プレイヤー向けの追いつき支援（EXPボーナス等）は解放済み地域数に応じて自動適用する案。

## 5. リセット設定（2.0）

| 設定 | 選択肢 |
|---|---|
| レベル | リセット／引き継ぎ |
| 装備・所持品 | リセット／引き継ぎ／シーズン限定品のみ削除 |
| 通貨 | リセット／引き継ぎ |
| クエスト・ダンジョン・ボス進行 | 常にリセット |
| アカウント・称号・コスメ・実績・歴代記録 | 常に保持 |

## 6. 終了・リセット処理（冪等）

各ステップの完了をシーズン行に記録し、途中停止後は未完了のステップから再開する。同じステップを2回実行しても結果が変わらないようにする。

1. 新規ランキング加算を停止
2. ボス討伐・ダンジョン記録を確定
3. ランキングを最終集計
4. 結果を履歴（英雄の記録）へ保存
5. シーズン報酬を付与（付与済みフラグで二重付与防止）
6. シーズン進行データを初期化（設定に従う。旧シーズンのデータは削除せず `season_id` で分離して保持）
7. 次シーズンを生成し開始日時を設定

## 7. 英雄の記録

過去シーズンのランキング・討伐記録・称号を閲覧できるUIとNPC。データは③記録データ（DATABASE_SCHEMA.md）から読む。
